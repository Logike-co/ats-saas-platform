# Código y Diseño Técnico

## Stack Tecnologico Definitivo

| Categoria | Tecnologia | Proposito |
| :--- | :--- | :--- |
| Lenguaje | TypeScript (estricto) | Unificar tipado en frontend y backend |
| Frontend | Next.js (React) | UI web del ATS |
| Backend | NestJS (Node.js) | API REST y logica de negocio |
| Base de datos | PostgreSQL | Persistencia relacional |
| ORM | Prisma | Modelado, migraciones y acceso a datos |
| Autenticacion | Keycloak + NextAuth (OIDC) | SSO, sesiones y control de acceso |
| Colas | Redis + BullMQ | Procesamiento asincrono |
| Testing FE | Vitest | Unitarias frontend |
| Testing BE | Jest | Unitarias e integracion backend |
| Testing E2E | Playwright | Pruebas end-to-end |
| Calidad | ESLint + Prettier | Estandares de codigo |
| CI | GitHub Actions | Validacion automatizada |

## Estructura del Monorepo

Se adopta una estructura simple y escalable:

```text
lti-ats/
├── apps/
│   ├── frontend/                # Next.js
│   └── backend/                 # NestJS
├── packages/
│   ├── shared/                  # Tipos compartidos, contratos, utilidades
│   └── config/                  # Configuracion compartida (eslint/tsconfig)
├── infra/
│   ├── docker-compose.yml
│   └── scripts/
└── docs/
```

## Diseno del Backend (NestJS)

### Modulos por feature

- `jobs`
- `applications`
- `assessments`
- `interviews`
- `offers`
- `notifications`
- `audit`
- `tenancy`
- `auth`

### Capas internas por modulo

- `domain`: reglas de negocio y transiciones de estado.
- `application`: casos de uso y orquestacion.
- `infrastructure`: repositorios Prisma, clientes externos, colas.
- `api`: controllers REST, DTOs y validaciones.

## API y Contratos

- Estilo: **RESTful JSON**.
- Versionado: `/api/v1`.
- Validacion de entrada backend: `class-validator` + `class-transformer`.
- Validacion frontend: `zod` para formularios y contratos de consumo.
- Convencion de respuesta de error: `code`, `message`, `traceId`, `details`.

## Autenticacion y Sesion (Recomendacion)

Se recomienda **NextAuth con proveedor OIDC (Keycloak)** para frontend.

Razon:

- integracion nativa con Next.js y middleware;
- manejo de sesion seguro en servidor;
- menor complejidad que implementar flujo OIDC manual;
- facilita proteccion de rutas por rol.

### Flujo resumido

1. Usuario inicia sesion en Keycloak.
2. NextAuth gestiona callback OIDC y sesion.
3. Frontend consume API con access token.
4. Backend valida JWT (issuer, audience, firma, expiracion) y rol.
5. Capa tenancy fuerza `tenant_id` en contexto por solicitud.

## Diseno Asincrono y Colas

Las colas se aplican en `notifications` y tareas diferidas:

- envio de emails transaccionales;
- recordatorios de entrevistas;
- reintentos ante fallos de SMTP;
- procesos no bloqueantes de auditoria/eventos.

### Patron de uso

- El caso de uso principal persiste cambios.
- Se emite evento interno.
- Se encola job BullMQ.
- Worker procesa, registra resultado y aplica reintentos.

## Convenciones de Codigo

- Idioma de codigo: ingles.
- Idioma funcional/documentacion: espanol.
- Tipado estricto obligatorio en TypeScript (`strict: true`).
- Naming consistente por feature y responsabilidad.

## Testing y TDD

- **TDD obligatorio** para desarrollo nuevo.
- Unit tests en frontend (Vitest) y backend (Jest).
- E2E con Playwright para flujos criticos.
- Cobertura minima objetivo: `90%` en logica critica.

## Logging, Metricas y Salud

- Logging estructurado con `pino`.
- Correlacion por `traceId`.
- Exposicion de health checks para API, DB, Redis y dependencias criticas.
- Metricas operativas para latencia, errores y throughput.

## Pipeline CI (GitHub Actions)

Pipeline minimo obligatorio en cada pull request:

1. Instalacion de dependencias (`pnpm`).
2. Lint.
3. Format check.
4. Tests unitarios.
5. Tests E2E (segun estrategia por rama/entorno).

No se permite merge si alguna validacion falla.
