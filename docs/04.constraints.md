# 🚧 Restricciones

## Restricciones de Negocio y Entrega

- **Equipo:** 1 desarrollador, apoyado por IA.
- **Plazo objetivo:** MVP tecnico en `2 meses`.
- **Presupuesto:** minimo posible (enfoque `low-cost`).
- **Mercado inicial:** PYMEs.
- **Idioma inicial:** interfaz y contenido en espanol.

## Restricciones de Plataforma e Infraestructura

- **Hosting objetivo:** VPS.
- **Entornos minimos:** `dev` y `prod`.
- **Arquitectura de despliegue:** consolidada y simple para reducir costo operativo.

## Restricciones Tecnologicas (Decision Recomendada)

Para balancear mantenibilidad, velocidad y baja complejidad operativa se adopta:

- **Backend:** Node.js con NestJS.
- **Frontend:** React con Next.js.
- **Base de datos:** PostgreSQL.
- **AuthN/AuthZ:** Keycloak (OIDC/OAuth2), desplegado en el mismo VPS en fases tempranas.
- **Orquestacion local/prod:** Docker Compose.

## Decision Arquitectonica Base

Se establece como restriccion de fase inicial un enfoque de **monolito modular en backend** (no microservicios), con frontend desacoplado.

Razon principal:

- reduce complejidad para un equipo de una sola persona;
- minimiza costo en VPS;
- facilita mantenibilidad y evolucion incremental;
- evita sobrecarga operativa temprana de microservicios.

## Restricciones de Integraciones Externas

- Se permiten integraciones de bajo costo y/o gratuitas.
- Se evita dependencia temprana de servicios SaaS de pago no esenciales.
- Notificaciones se contemplan mediante componente dedicado (modulo interno) e integraciones externas progresivas.

## Restricciones Legales y Compliance (Estado Actual)

- No existen obligaciones contractuales especificas en esta fase.
- Como restriccion de diseno, se aplican controles base de proteccion de datos personales para no generar deuda regulatoria futura.

## Restricciones de Operacion y Soporte

- Operacion inicial simplificada para ser gestionada por una sola persona.
- Automatizacion prioritaria en build, despliegue y monitoreo basico.
