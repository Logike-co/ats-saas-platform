# 🎯 Atributos de Calidad

## Objetivo

Definir los atributos de calidad prioritarios para el ATS de LTI y sus metas medibles, de forma que guien decisiones de arquitectura, implementación y operación desde las primeras iteraciones.

## Prioridades de Calidad (ordenadas)

1. **Mantenibilidad**
2. **Costo**
3. **Rendimiento**
4. **Seguridad**
5. **Disponibilidad**
6. **Observabilidad**

## Metas y Criterios por Atributo

### Disponibilidad

- **Objetivo:** `99.5%` mensual.
- **Estrategia inicial:** enfoque `low-cost` con tolerancia a indisponibilidades acotadas.
- **Implicación:** la alta disponibilidad avanzada (multi-zona, failover activo-activo) se difiere para fases de crecimiento.

### Rendimiento

- **Objetivo general:** tiempos de respuesta en **milisegundos** para operaciones frecuentes del sistema.
- **Escenarios foco:** consulta de vacantes, listado de candidaturas, cambio de estado y registro de feedback.
- **Criterio de aceptación inicial:** operaciones de uso cotidiano percibidas como respuesta inmediata por usuarios de negocio.

### Escalabilidad

- **Estrategia inicial:** escalado **vertical**.
- **Evolución esperada:** incorporar escalado horizontal cuando la carga de tenants y usuarios concurrentes lo justifique.

### Seguridad

- **Control de acceso reforzado:** **MFA obligatorio para administradores**.
- **Protección de datos en tránsito:** cifrado TLS en todas las comunicaciones externas.
- **Protección de datos en reposo:** cifrado de almacenamiento y/o base de datos en entornos productivos.

### Trazabilidad y Auditoría

- **Eventos auditables mínimos:** creación, cambio de estado, asignaciones y decisión final.
- **Retención de logs:** `3 meses`.

### Recuperación ante Desastres

- **RPO:** `24 horas`.
- **RTO:** `4 horas`.
- **Implicación:** estrategia de backup y restauración diaria con procedimientos validados.

### Mantenibilidad y Calidad de Código

- **Cobertura objetivo:** `90%` en lógica crítica de negocio.
- **Estándar de calidad:** foco en alta calidad de código (revisiones, pruebas automatizadas y control de deuda técnica).

### Observabilidad

Mínimos requeridos desde el arranque:

- **Logs estructurados**
- **Métricas operativas**
- **Health checks** de componentes clave

### Privacidad y Ciclo de Vida de Datos

- **Decisión actual:** no se implementa aún anonimización/eliminación automática por tiempo.
- **Nota de arquitectura:** esta capacidad debe quedar prevista para una fase posterior por requisitos regulatorios o comerciales.

## Trade-offs Aceptados en Fase Inicial

- Se prioriza una arquitectura costo-eficiente sobre niveles altos de resiliencia compleja.
- Se privilegia velocidad de construcción con una sola persona desarrolladora, preservando calidad en el núcleo de negocio.
- Se establecen controles de seguridad esenciales desde el inicio para evitar retrabajo futuro.
