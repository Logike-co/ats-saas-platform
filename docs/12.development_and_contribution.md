# Ambiente de Desarrollo y Contribución

## 🚀 Local Setup (En menos de 2 min)

### Requisitos

- Node.js 20+
- pnpm
- Docker + Docker Compose

### Pasos de arranque

1. Clonar repositorio.
2. Configurar `.env.dev`.
3. Levantar dependencias con Docker Compose (PostgreSQL, Redis, Keycloak).
4. Instalar dependencias: `pnpm install`.
5. Ejecutar migraciones: `pnpm --filter backend prisma migrate dev`.
6. Arrancar apps:
   - `pnpm --filter backend dev`
   - `pnpm --filter frontend dev`

## 🤖 Estándares para Agentes IA (Reglas MDC)

El uso de IA en desarrollo debe respetar las mismas reglas de calidad que el desarrollo manual:

- no bypass de tests/lint;
- no introducir secretos en codigo;
- mantener coherencia con arquitectura modular;
- toda contribucion generada por IA debe pasar por validacion humana y CI.

## 📐 Estructura de Contribución y Código

### Modelo de ramas

- `main`: rama estable de produccion.
- `develop`: integracion continua de trabajo en curso.
- `feature/*`: ramas de funcionalidad.
- `hotfix/*`: correcciones urgentes desde `main`.

### Convencion de commits

Se adopta **Conventional Commits**:

- `feat:`
- `fix:`
- `refactor:`
- `test:`
- `docs:`
- `chore:`

### Convenciones tecnicas

- TypeScript estricto.
- Arquitectura modular por features.
- API REST versionada (`/api/v1`).
- Codigo en ingles; documentacion funcional en espanol.

## 🤝 Ciclo de Calidad Obligatorio

### Pull Request obligatorio

Toda contribucion llega por PR, con checklist de calidad:

- lint y format en verde;
- tests unitarios y de integracion en verde;
- evaluacion de impacto en base de datos/migraciones;
- evaluacion de impacto en seguridad (auth, permisos, tenant);
- documentacion actualizada cuando aplique.

### Aprobacion

- Minimo 1 aprobacion antes de merge (en equipo unipersonal: autoaprobacion con checklist estricto).

### CI obligatorio (GitHub Actions)

Pipeline minimo:

1. Install dependencies.
2. Lint.
3. Format check.
4. Tests.
5. (Opcional segun rama) E2E.

No se permite merge con checks fallidos.

### Calidad local previa

- Hooks con `husky` + `lint-staged` para validacion temprana.

## 📖 Documentación y Seguridad

### Gestion de trabajo

- Uso de **GitHub Issues/Projects** para backlog, trazabilidad y prioridades.
- Plantillas obligatorias para Issue y PR.

### Definition of Done (DoD)

Una tarea se considera terminada solo si cumple:

- codigo implementado y revisado;
- pruebas automatizadas actualizadas/pasando;
- documentacion actualizada;
- despliegue validado en entorno `dev`;
- sin regresiones conocidas en funcionalidades criticas.

### Seguridad en contribucion

- secretos solo en variables de entorno/secret managers;
- nunca commitear credenciales;
- minimo privilegio en tokens y accesos.
